# StarRailAutoBattle 启动器

一个在 Windows 本机运行的桌面小工具（简体中文、浅色界面），分“视频”“凹分序列”和“游戏”三页：

- **视频页**：填 B 站链接（可选起点、终点），程序在自己的录制窗口里未登录播放并录下这一段，再在本机识别行动轴（不调用大模型），结果存成文本文件；链接录不了时可改用自录视频文件；
- **凹分序列页**：编辑凹分检定用的预期序列（一整场战斗的行动顺序和检定条件），边输入边检查格式，保存后供自动操作的程序读取；
- **游戏页 · 启动游戏**：像在资源管理器里双击一样，打开你选的 `.exe` 或 `.lnk` 快捷方式；
- **游戏页 · 只识别已运行游戏**：不启动任何程序，找到已经由官方启动器打开的游戏窗口，尝试还原并切到前台。

**交付形式：** 便携版单文件 `StarRailAutoBattle.exe`（自包含 .NET 运行时，用户电脑不需要另外安装 .NET，不需要安装程序）。

## 技术方案

| 项 | 选择 |
| --- | --- |
| 语言 / 框架 | C# 13 / .NET 10，WPF 桌面界面 |
| 启动程序 | Win32 `ShellExecuteEx`（默认动作，与资源管理器双击相同；不使用 `runas`，不拼接命令行） |
| 读取快捷方式 | Windows Shell `IShellLink`（只读，不调用 `Resolve`，不修改 .lnk） |
| 识别窗口 | `QueryFullProcessImageName` + `EnumWindows`，按“进程文件名 + 完整程序路径”匹配，从不只凭窗口标题 |
| 置前 | `ShowWindowAsync(SW_RESTORE)` + `SetForegroundWindow`，然后用 `GetForegroundWindow` 核实结果；不使用模拟按键等绕过系统限制的手段 |
| 权限 | 应用清单为 `asInvoker`，从不自行请求管理员权限 |
| 视频录制 | Microsoft Edge WebView2（Windows 11 自带）在独立窗口里播放，`CapturePreviewAsync` 截取窗口画面，OpenCV 写成 Motion-JPEG `.avi`；不下载原视频文件 |
| 行动轴识别 | `src/AxisRecognizer.Core`（OpenCV），见 [docs/action-axis-knowledge-base.md](docs/action-axis-knowledge-base.md) |

## 开发环境与命令

需要：Windows 10/11 x64，[.NET SDK 10.0.100 或更新的 10.0 版本](https://dotnet.microsoft.com/download)（见 `global.json`）。不需要 Node.js。

```powershell
dotnet restore StarRailAutoBattle.slnx
dotnet build StarRailAutoBattle.slnx
dotnet test StarRailAutoBattle.slnx          # 自动化测试
dotnet run --project src/GameLauncher         # 开发运行
```

生成发布用的 exe（先跑测试，再打包到 `dist\StarRailAutoBattle.exe`）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\publish.ps1
```

等价的单条命令：`dotnet publish src/GameLauncher -c Release -r win-x64 -p:DebugType=none -o dist`

`bin/`、`obj/`、`dist/` 等构建产物已在 `.gitignore` 中忽略。

## 使用：视频页

1. **B 站视频链接**：可直接粘贴 B 站 App 复制的分享文字（`【标题】 https://…`）、`www.bilibili.com/video/BV…` 链接、`b23.tv` 短链接或单独的 BV 号。分享参数会被去掉。目前只支持 B 站。
2. **起点、终点（可选）**：`1:14` 或 `74`（秒）。都不填 = 整段；只填起点 = 到结尾；只填终点 = 从开头。
3. **自录视频文件（可选）**：链接录不了时选你自己录好的视频（mp4、mkv、mov、avi、webm、flv）。选了文件就直接识别文件，不打开链接；起点、终点同样有效。
4. 点 **启动**：
   - 链接：在**屏幕外的隐藏窗口**里播放（不显示、不抢前台、不出现在任务栏），静音，关闭并隐藏弹幕，选当前账号（或未登录）可用的最高清晰度，跳到起点录到终点，文件为每秒 15 帧。截图跟不上实时播放时会放慢播放速度（1080P 实测约 0.55×），文件时间轴仍等于视频时间，所以录制用时会比片段长（74 秒的片段约 2～3 分钟）。遇到要求登录、人机验证、黑屏（受保护视频）、找不到播放器或长时间不播放时**停止并说明原因**，不会绕过，并提示改用自录文件。
   - 然后逐帧识别行动轴（每秒视频取 15 帧；画面需稳定 0.3 秒才算一个状态）。画面太小（游戏画面高度低于暂定的 720 像素）时，结果开头和界面上都会提示可信度低。
   - 界面上**不直接显示结果文本**，只显示进度和完成情况。
5. **编辑结果**：打开结果的可编辑副本 `result_edit.txt`（首次点击时从原始结果复制）。工具生成的原始结果 `result.txt` 保持只读。编辑后的副本只供你自己使用，不会回流到知识库。
6. **打开结果文件夹**：查看本次运行的全部文件。

**清晰度与登录（实测，2026-10-27）：** B 站未登录时只开放 360P，480P～1080P 要求登录，1080P 60 帧要求大会员。未登录时录到的是 360P，识别结果会带“清晰度不足”提示。

- 视频页的 **“登录 B 站…”** 会打开 B 站登录页（推荐用 B 站 App 扫码），登录只需一次。登录在本程序**自己的浏览器**里进行，账号和密码只由 B 站页面处理；程序只检查 B 站的会话 Cookie 是否存在（名称和有效期，不读取内容），之后录制会自动选这个账号能看的最高清晰度。
- **不会使用 Edge 浏览器里已有的 B 站登录**：那需要读取并解密 Edge 保存的登录凭据，Edge 本身会阻止，这也是盗号软件的做法。
- **“退出登录”** 会删除本程序浏览器里的全部 Cookie，不影响 Edge。

## 使用：凹分序列页

规则和完整写法见 [docs/score-retry-check.md](docs/score-retry-check.md)。

1. **打开**：选“（新序列）”从空白开始，或选一份已保存的序列。有未保存的修改时，切换序列或关闭程序会先询问是否保存。
2. **编辑**：一行一步，`序号 单位 [招式] [目标] [@ 条件]`，用空格隔开，方括号里的可以不填（目标不填时默认打 boss，没有 boss 时用游戏默认目标），例如 `2 昔涟 战技 敌2  @ 轮次=1 行动值=120~160`；`== 换波 ==`、`== 转阶段 ==` 之后序号从 1 重新开始。页面内的“写法说明”有完整示例。
   - 打字时（含输入法）：打完行首序号接着打字，会自动补一个空格；已经有空格的地方再打空格不添加；格式里用不到的符号（如 `→`、`|`、`；`）不添加。`#` 后的注释不受限制，粘贴的内容不改动（规则 R48）。
3. **检查**：停止输入约 0.3 秒后自动检查，显示行动数、检定处数，以及每个问题的行号（**错误**：改好前不能用于检定；**提醒**：允许但可能写错）。点问题会跳到那一行。单位名称按识别知识库检查（启动器打开时读取一次）。
4. **保存**：填名称后点“保存”；改了名称再保存就是“另存为”，同名已存在时会先询问是否覆盖。有错误也能保存，但会先提醒。

## 使用：游戏页

1. **游戏入口**：手动输入路径或点“浏览文件…”。支持真实 `.exe` 和 `.lnk` 快捷方式。下方会显示文件的**实际类型**（按文件内容判断，不按显示名），以及快捷方式的目标、参数、起始位置和程序要求的权限。
   - 资源管理器默认隐藏 `.lnk` 扩展名：显示为 `XXX.exe` 的快捷方式，真实文件名是 `XXX.exe.lnk`。如果手动输入了不带 `.lnk` 的名称，应用会提示。
   - 从资源管理器“复制文件地址”粘贴的带引号路径会自动去掉引号。
2. **运行模式**：选“启动游戏”或“只识别已运行游戏”，点“启动”。
3. **识别窗口用的游戏程序（可选）**：入口是官方启动器时，在这里选游戏本体 `.exe`，用于识别游戏窗口；留空则使用入口实际指向的程序。

### 游戏页点击“启动”后的实际顺序

1. 校验路径。不合格：只显示错误，**不启动程序**。
2. 处理游戏：
   - **启动游戏**：`ShellExecuteEx` 打开入口。若程序清单要求管理员权限，Windows 会弹出 UAC 确认，由你决定；选“否”会显示“已取消启动”。程序若在 3 秒内退出，会显示退出码。随后最多等待 90 秒检测游戏窗口，找到后尝试切到前台（可点“停止等待窗口”）。
   - **只识别已运行游戏**：不创建任何进程。找到窗口就还原并请求置前；没找到时提示“未检测到已运行的游戏（…），请先通过官方启动器启动，再返回本应用重试。”
3. 状态区显示结果；“诊断详情”里有操作阶段和 Windows 错误码（只含文件名，不含完整路径）。

### 窗口识别规则

- 进程文件名必须与目标程序相同；能读取进程完整路径时，路径也必须一致（同名但不同位置的程序不算）。
- 只考虑可见、无所有者、非工具窗口的顶层窗口（最小化的也算）。
- Windows 不允许读取进程路径时，**不会自动切换**，而是列出候选窗口请你确认。
- 置前后会核实前台窗口；Windows 拒绝时如实提示，请手动点击任务栏中的游戏图标，或点“切换到游戏窗口”重试（由你点击按钮时，系统通常允许切换）。

## 关于星穹铁道

在开发机上核查（只读）得到的事实：

- 测试快捷方式 `StarRail_for_test.exe` 的真实文件名是 `StarRail_for_test.exe.lnk`，指向游戏本体 `StarRail.exe`（miHoYo 签名有效），无参数，起始位置为游戏目录。
- `StarRail.exe` 的嵌入清单声明 `requestedExecutionLevel level="requireAdministrator"`。
- 旧版用 Node.js `child_process.spawn`（底层 `CreateProcess`）启动。`CreateProcess` 无法启动要求管理员权限的程序，返回 `ERROR_ELEVATION_REQUIRED (740)`，而 libuv 把它映射为 `EACCES`（errno `-4092`）。在同一台电脑上用另一个声明 `requireAdministrator` 的系统程序复现了完全相同的 `spawn … EACCES -4092`。

因此，旧版报错**最可能**的原因是 `spawn` 这条路径不能触发 UAC，而不是文件读取权限或安全软件拦截。本应用改用 `ShellExecuteEx`，由 Windows 按正常流程弹出 UAC。

**Windows 实机验证结果（开发者本机）：** 选择星铁快捷方式和直接选择 `StarRail.exe` 都能打开游戏；先用官方启动器启动游戏后，“只识别已运行游戏”模式可以把游戏窗口切到前台。若在其他电脑上游戏要求必须经官方启动器启动：入口选官方启动器（或其快捷方式），“识别窗口用的游戏程序”选 `StarRail.exe`；或者先用官方启动器开游戏，再用“只识别已运行游戏”模式。本应用不会绕过启动器、反作弊或 UAC。

另外：官方启动器和游戏通常以管理员身份运行，而本应用以普通权限运行。在某些系统上 Windows 可能因此不允许本应用还原最小化的游戏窗口或把它切到前台；应用会如实提示，请手动点击任务栏。

## 本机数据

- 偏好（上次的入口路径、识别用程序路径、模式）：`%LOCALAPPDATA%\StarRailAutoBattle\settings.json`。**视频链接不保存。**
- 诊断日志：`%LOCALAPPDATA%\StarRailAutoBattle\logs\launcher.log`（只记录文件名、错误码和阶段，不记录完整路径、快捷方式参数内容或网址；超过 512 KB 自动轮换）。
- 录制窗口的浏览器数据：`%LOCALAPPDATA%\StarRailAutoBattle\WebView2Recorder`（独立于你的 Edge；你在“登录 B 站…”里登录后，B 站的登录状态保存在这里，“退出登录”可清除；不读取 Edge 的登录信息或 Cookie）。
- 视频页每次运行的文件：`axis-data\video-runs\<时间>_<BV号或文件名>\`（仓库内，已被 `.gitignore` 忽略；用户电脑上的位置以后再定）：
  - `recording.avi` + `recording_info.txt`（链接录制：视频、标题、UP 主、页面转载声明、访问时间、清晰度、实际录到的区间、文件校验值）；
  - `result.txt`（只读原始结果）、`result_detail.tsv`（只读逐格明细）、`result_edit.txt`（点“编辑结果”后生成）、`run_info.txt`（知识库和工具版本、来源、帧数）。
- 凹分序列：`axis-data\sequences\<名称>.txt`（UTF-8 文本，一份序列一个文件，供自动操作的程序读取）。
- 视频页识别完成后点“生成凹分序列”：工具生成的原稿存为该运行文件夹的 `sequence_draft.txt`，同时填进“凹分序列”页（核对后由你保存）。
- 只有视频页在你点“启动”后访问 B 站；不上传任何本机路径，不需要任何 API Key。录到的视频只在本地算法沙箱内研究使用。

## 行动轴头像识别（开发中，识别工具 0.4.1）

从视频画面识别行动轴上的单位头像，在本机运行，**不调用大模型**。建库、盲测和纠正由开发者用命令行工具 `axis` 完成，完整说明见 [docs/action-axis-knowledge-base.md](docs/action-axis-knowledge-base.md)。知识库在 `axis-data/kb/`，只存本机，不进 Git。

**怎么识别**
1. 按格子边框的轮廓找出当前格和主轴各格，不依赖格子里的头像。
2. 每个头像去掉边框和行动值数字框，缩成 40×40，以**轮廓为主**（边缘 0.8 + 灰度 0.2，不比颜色）与知识库样本比较。加速等状态会让头像整体变色，不比颜色就能把不同状态认成同一单位。
3. 得分 ≥ 0.55 且领先第二名 0.05 才认定。参数依据：用户确认的样本里，同一单位 90% 的配对 ≥ 0.62，不同单位最高 0.48。
4. 视频每秒取 15 帧，当前格稳定 0.3 秒算一次行动。

**单位编号**
- 每种头像一个全局编号 `U0001`…，不分角色、召唤物、怪物；名称和类型只是注释，由用户确认。
- 知识库里没有的头像，在一次结果里给临时编号 `新01`…（同一编号 = 同一单位），并按外观、同一格的闪变、当前格与主轴格的进出关系分组，拿不准时只标“疑似”。
- 用户核对后用 `axis kb promote` 转为全局编号；也可存为“临时”单位方便查看，确认后再转正或合并。

**测试流程**：盲测片段只运行工具，原始结果只读；用户核对后把纠正写入知识库，另存修正后结果（`axis test correct` / `axis test rerun`）。

**目前效果**（知识库 v92，2026-10-28）：同一队伍的 4 段视频共识别出 30 余个单位；最新一段盲测（碎星王虫 1:09–2:09）修正后，20 条行动里 18 条认对单位，剩下 2 条是回合开始的白色闪光。

## 已知限制

- 星铁的启动与置前已在开发者本机验证；其他电脑的系统设置、启动器版本不同，结果可能不同。
- 如果游戏的反作弊阻止普通程序查询其进程路径，应用会改为请你确认窗口，不会自动切换。
- 快捷方式没有普通文件目标（如应用商店或安装程序创建的特殊快捷方式）时，仍可启动，但识别窗口需另外指定游戏程序。
- 只做了 x64 版本。
- 行动仍按“当前格换人”计数：同一单位连续行动会合成一条，回合中途插入的终结技不会记成插入行动（如 14-1），回合开始的白色闪光可能被记成一条“未知”。按画面事件（回合开始闪光、插入格、“我方/敌方行动中”字样）计数尚未实现。
- 行动轴布局只在 16:9 画面上标定过；360P 画面能否找到行动轴尚未验证。
- B 站页面结构变化时，录制可能失败（会提示“找不到视频播放器”），需要更新 `src/VideoRecorder/bilibili.js`。
