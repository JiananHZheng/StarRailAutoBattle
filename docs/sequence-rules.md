# 序列规则（已确认）

本文件是录制、识别、检定规则的唯一出处，代码和测试按编号引用（例如 `// R23`）。只收用户确认过的规则；没确认的放在文末“待确认”，不得当作规则实现。
来源：docs/score-retry-check.md（设计与实测记录）、docs/action-axis-knowledge-base.md、提交记录 5d310ed–e0925e5、和用户的商定（2026-10-27 至 10-29）。
新规则：用户确认后先追加到这里（带一行例子），再写代码。

## A. 环境与素材

- **R1** 游戏是 Windows 原生客户端，不在 Edge 或任何浏览器里运行；抓游戏画面不走浏览器/WebView 抓取。
  例：实战检定进程直接截取游戏窗口，不启动 WebView2。
- **R2** 只有 B 站视频录制用启动器自带的浏览器（WebView2，独立配置目录），不读取、不复用 Edge 的登录信息。
  例：录制器配置在 `%LOCALAPPDATA%\StarRailAutoBattle\WebView2Recorder`。
- **R3** B 站录制必须登录才能拿到 1080P（不登录只有 360P）；用户在启动器里自己登录，程序不输入账号密码。
  例：`recording_info.txt` 写着“登录状态：已登录 … 视频清晰度：1920×1080”。
- **R4** 不从外部直接调 B 站接口或用命令行下载（412 风控、下载被截断）；在录制器自己的页面里取视频流或截取播放画面；遇到 DRM 就停，不解密。
  例：请求 01:20–01:26 → 页面内取到 01:15–01:30 片段，1920×1080，7.6 MB。
- **R5** 录制或裁剪改动后检查输出分辨率，1080P 必须是 1920×1080，否则不算成功。
  例：输出 676×61（裁剪 bug）→ 失败，不能报告“录好了”。
- **R6** 盲测视频 BV18nVd6VEiB 永远不看画面，只在用户指定的片段上跑工具，再等用户答案。学习和标注只用三个开放视频：BV1EM8Q69EqZ（铁墓）、BV1vAgy6LE9G（绘世）、BV1pCaX6iEsU（亚婆离）。
  例：`scripts/check-samples.ps1` 遇到含 BV18nVd6VEiB 的样本直接跳过。
- **R7** 素材只在本地 `axis-data/` 沙箱里用，不转载、不上传；链接里的分享参数（vd_source）不写进提交的文件。
  例：`recording_info.txt` 记“链接：…/BV1EM8Q69EqZ/（已去掉分享参数）”。

## B. 序列里记什么

- **R8** 一份序列对应一整场战斗：从战斗开始到结算画面。混沌回忆上下半场之间算一次换波。
  例：上半场结束 → `== 换波 ==` → 下半场从 `1` 开始。
- **R9** 只记我方单位（角色、忆灵、召唤物、特殊单位）；敌方行动和 boss 机制条目（红色菱形）都不记。
  例：铁墓 0:50 附近的敌方回合、2:52 的 boss 机制条目不出现在序列里。
- **R10** 主轴行动 `n` 是本段第 n 次主轴行动；被控制跳过的回合也算。
  例：昔涟被冻结跳过的回合仍写 `5 昔涟`。
- **R11** 额外行动 `n-i` 挂在被它打断的主轴行动 n 下面；连续释放的多个终结技依次是 n-1、n-2…；本段第一次主轴行动之前的写 `0-1`、`0-2`。
  例：长夜月的主轴行动 7 中，昔涟终结技进当前格还没放，又按了忆灵昔涟的终结技 → `7-1 昔涟 终结技`、`7-2 忆灵昔涟 终结技`。
- **R12** 额外回合不能算作主轴行动。
  例：小伊卡在风堇回合中途的额外回合写 `12-1 小伊卡`，不是 `13 小伊卡`。
- **R13** 换波、转阶段写成特殊行动 `== 换波 ==`、`== 转阶段 ==`，之后序号从 1 重新开始。
  例：`9 迷迷` → `== 转阶段 ==` → `1 昔涟`。
- **R14** 额外行动不全是终结技：看到终结技启动的才写“终结技”，只有四角星标记的额外行动不写招式。
  例：`3-1 长夜月 终结技`（有启动）；`9-3 小伊卡`（只有四角星）。
- **R15** 阿哈时刻写成一行主轴行动，它触发的欢愉技写在括号里，不拆成额外行动。
  例：`5 阿哈时刻（含阿哈时刻附加行动：爻光、真珠）`。

## C. 文本格式

- **R16** 一行一步：`序号 单位 [招式] [目标] [@ 条件]`，空格分隔，`#` 后是注释；招式是普攻、战技、终结技。
  例：`2 昔涟 战技 敌2  @ 轮次=1 行动值=120~160  # 第1波`。
- **R17** 目标不写箭头。旧写法 `→敌2`、`->敌2` 仍能读，保存时去掉箭头。不发明新语法。
  例：写 `2 昔涟 战技 敌2`，不写 `2 昔涟 战技 →敌2`。
- **R18** 目标有两种写法，可以混用：从左数 `敌1`、`敌2`…（换波或有敌人倒下后按当时位置重数）；以 boss 为基准 `敌(0)`、`敌(-1)`、`敌(+1)`…（没有 boss 或有多个 boss 时只用从左数）。我方目标写 `我1`、`我2`…（画面表现待学）。
  例：boss 左边那只小怪写 `敌(-1)`，场上从左数第一只写 `敌1`。
- **R19** 不填目标时，操作上默认打 boss（`敌(0)`），没有 boss 时用游戏默认目标；从视频识别出的序列暂不填目标。
  例：`3 记忆主 普攻` → 自动操作打 boss。
- **R20** 条件 `@ 轮次=… 行动值=…` 可只写一项，值可写区间；换波、转阶段默认不读，写了 `@` 才读。
  例：`== 转阶段 ==  @ 行动值=50~100`。
- **R21** 单位写名称或 U 编号；知识库里没有的名称、一个名称对应多个单位、敌方单位都报错。识别不出写“未知”并注明，由人工改。
  例：`13-9 未知 终结技  # 单位看不清，请改成名称或 U 编号` → 格式检查报错，直到改成 `13-9 风堇 终结技`。
- **R22** 全角符号和全角数字都认。
  例：`２ 昔涟 敌（－１） ＠ 行动值＝１２０～１６０` 和半角写法等价。

## D. 画面识别

- **R23** 战斗开始 = 秘技后先黑屏，然后画面中间出现一条白线（连续两帧），不是某个界面元素出现。没看到时从第一个行动或第一条横幅算起，并注明“未检测到战斗开始”。
  例：三个开放视频都在 7–8 秒看到白线；铁墓草稿写“# 战斗开始（视频 0:08.0）”。
- **R24** 换波 = 画面上方出现“战斗开始 x/n”横幅；战斗开始后的第一条是第 1 波，之后每出现一条算一次换波，4 秒内重复出现不算。
  例：绘世 3:07.9 的横幅 → `== 换波 ==`。
- **R25** 转阶段 = boss 血条到 0% 且血条上方亮着的红点少一个，并保持 2 秒（特效遮住约 0.5 秒不算）；打掉这一阶段的那次行动留在旧阶段。
  例：绘世 7:02.2 红点从 2 个变 1 个 → `== 转阶段 ==`。
- **R26** 战斗结束 = “结束战斗”或“挑战成功”横幅连续两帧。失败画面还没有样本。
  例：铁墓 9:50–9:57：“结束战斗” → 黑屏 → “挑战成功”。
- **R27** 回合起点 = 当前格白闪（格内 80% 以上近白），或当前格的标记、单位改变并保持 0.2 秒；白闪后 0.4 秒内的改变算同一回合。同一单位连续两个回合只能靠白闪区分。
  例：终结技光束扫过只有约 47% 近白，不算白闪。
- **R28** 回合类型看当前格左侧标记：青色圆点 = 我方主轴；青色四角星（用户说的“小叉号”）= 额外行动；红色圆点 = 敌方；红色菱形 = boss 机制条目。
  例：当前格是青色四角星 → 写成 `n-i`。
- **R29** 终结技由按键操作：队伍栏头像亮起是启动，按下释放键才释放。队伍栏每个头像右边的终结技按钮亮着 = 就绪，按下后熄灭。启动信号不是插入卡（见 R45）。
  例：2 号位按钮就绪 1 秒后熄灭 → 2 号位在这一刻释放了终结技。
- **R30** 队伍栏位置 → 单位只用用户给的队伍（`--team` 或启动器“队伍”栏），不从画面学、不猜；没给队伍时只标“队伍第几位”。
  例：`axis sequence … --team 昔涟,长夜月,风堇,记忆主`；自己学过一次，把长夜月的终结技标成了忆灵昔涟。
- **R31** 招式不能靠战技点判断（有的战技不耗点，有的普攻不回点）；看选招状态里被放大的按钮，取行动开始执行前最后一次清楚的读数。
  例：铁墓 0:17.7 先选普攻 1.5 秒，最后几帧换成战技 → 写 `战技`。
- **R32** 轮次和剩余行动值在行动进行中读（行动中不变），同一步至少两帧一致；任何一位数字拿不准就整条作废，按待定处理。
  例：读到“⌛2 | 238”两帧一致 → `轮次=2 行动值=238`。

## E. 检定

- **R33** 和预期序列相比，多了、少了、顺序反了，或类型（主轴、额外、特殊）不对，都判失败；结算时序列没走完，或走完后又出现行动，也判失败。
  例：预期 `3-1 长夜月 终结技`，实战没有这一步 → 失败。
- **R34** 招式和目标不参与判定。
  例：预期 `2 昔涟 战技`，实战是普攻 → 不因此判失败。
- **R35** 看不清、拿不准判待定，不判失败（宁可不重开）；每步在出现后 1 秒内给出判定。
  例：单位认不出 → 输出待定，继续看下一步。
- **R36** 判失败或待定后继续看画面，下次检测到战斗开始（R23）就从第 1 步重新比对。
  例：重开后黑屏白线出现 → 比对回到 `1`。
- **R37** 检定是单独的进程：自己截取游戏窗口，每个事件输出一行 JSON；只读屏幕，不读内存、不注入游戏进程。重开和模拟操作由队友的程序负责。
  例：每检测到一步就输出一行 JSON 供队友程序读取（字段格式还没定）。

## F. 单位与知识库

- **R38** 每个不同的行动轴头像一个全局编号 `U0001…`：同一头像同一编号，不同头像不同编号；颜色或状态变体（如发红）是同一单位。名称是用户的备注，用户确认后才写入。
  例：发红的昔涟头像仍是昔涟的 U 编号，不新开编号。
- **R39** 盲测中的新头像用临时编号 `新01…`，知识库冻结；用户核对后才通过 `axis kb promote` 转正。拿不准标“疑似”，不自动合并。
  例：用户答“新01 = U0012” → 合并进 U0012。
- **R40** 屏幕文字（如“这里”）和轴底的剩余行动值条不是单位。
  例：识别结果里出现“这里”格 → 丢弃，不进知识库也不进序列。

## G. 测试与流程

- **R41** 每次改检测器后，在主目录跑 `pwsh scripts/check-samples.ps1`，报告逐条差异和按类型的精确率、召回率；`expected.txt` 由用户确认，不为了通过而修改。
  例：改了白闪阈值 → 跑脚本 → 报告“铁墓：不一致 3 处”。
- **R42** 和用户答案比对时先对齐，再把每处差异交给用户裁定（工具错 / 答案笔误 / 不确定）；只有“工具错”才变成修正和知识库数据，工具的原始输出不改。
  例：工具漏了一步导致后面序号整体错位 → 先对齐，只报这一处。
- **R43** 测试遗留文件：自己的临时输出（草稿区、临时程序）立刻删；录像和盲测结果先列清单（带大小），用户同意再删。
  例：3 分钟录像约 1.2 GB → 列出来问用户。
- **R44** 规则不清楚时先问；用户回答后先写进本文件（带例子），再写代码和测试。
  例：用户确认“星标额外行动不写招式” → 先加 R14，再改 EventAnalyzer。

## H. 后续确认（按确认顺序追加）

- **R45** 插入卡（当前格右边的拱顶小卡）不可靠：它和终结技启动不是同一时刻，不能用来判断启动，也不能用来给终结技计数。终结技只看队伍栏（R29）。（用户 2026-10-29，回答 Q1）
  例：出现一张新插入卡，但队伍栏没有任何一位熄灭 → 不记终结技。
- **R46** 昔涟那一位的水晶心形图标也有可读的“亮/灭”：亮 = 就绪，按下后熄灭，和其他位置的终结技按钮一样按 R29 读，不再靠插入卡或四角星认她的终结技。（用户 2026-10-29，回答 Q5）亮和灭具体长什么样待学（Q5a）。
  例：昔涟在 1 号位，心形图标由亮转灭并保持 1 秒 → `n-i 昔涟 终结技`。
- **R47** 识别要跟得上快的操作：每一步在出现后 0.5 秒内认定（比 R35 的 1 秒更紧）。（用户 2026-10-29：“识别时间看看能不能提速到 0.5 秒，考虑到视频操作可能会比较快”）
  例：Release 版每帧约 27 ms，按每秒 15 帧截图，回合在开始后约 0.25 秒（3 帧一致）认定。
- **R48** 启动器手动编辑序列时：行首序号（`3`、`3-1`）打完后接着打别的字，自动在中间补一个空格；已经有空格的地方再打空格不添加；格式里用不到的符号（如 `→`、`|`、`;`）打了也不添加。`#` 后的注释不受限制；粘贴的内容不改动，照常由格式检查报错。（用户 2026-10-29）
  例：依次打 `3`、`昔`、`涟`、空格、空格、`|`、`战技` → 编辑框里是 `3 昔涟 战技`。
